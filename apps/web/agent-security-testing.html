SECURITY ENGINEERING GUIDE

AI agent security testing that checks behavior, not just prompts.

AI agents are software systems with permissions, tools, data boundaries, and side effects. A serious security test must evaluate the complete path from untrusted input to proposed action.

Updated October 2026 · 5 min read

An agent can produce a polite answer and still be unsafe. The security boundary is crossed when it proposes a refund, changes an order, creates a ticket, reads another tenant’s data, or moves sensitive context into a side effect.

This matters most for agencies shipping Shopify and WooCommerce support agents. A realistic failure is an untrusted order note that convinces the agent to propose a $120 refund, apply an unauthorized discount, or change an order outside the customer’s permissions.

What should an agent security test cover?

A useful suite tests the agent’s decisions under pressure, not only whether it follows a happy-path instruction. Start with five layers:

  1. Instruction hierarchy. Place malicious instructions in retrieved content and verify that data remains data—not authority.
  2. Authorization boundaries. Test role impersonation, cross-tenant object access, and requests that rely on conversational claims instead of server-side permissions.
  3. Tool-call integrity. Bind arguments to trusted context, reject malformed structures, and block tools that are not explicitly registered.
  4. Side-effect safety. Evaluate read-then-write chains, data exfiltration through tickets, and business-policy boundaries.
  5. Runtime enforcement. Put a fail-closed guard in front of execution so a new prompt or model regression cannot directly reach a side effect.

Why single-turn jailbreak tests are not enough

Real failures are often composed: a lookup creates context, an attacker changes the meaning of that context, and a second tool performs the side effect. That is why AgentGuard records the input, every proposed tool call, the policy decision, and whether execution was allowed or suppressed.

The useful result is not “the model refused.”The useful result is evidence that the system cannot cross an authorization boundary—even when the model proposes the action.

A production-ready workflow

Connect a safe Staging or mock endpoint, run a professional adversarial suite, review the Security Blueprint, and apply only the controls you approve. AgentGuard sends synthetic JSON requests and evaluates returned tool_calls; it does not execute those calls itself. Your endpoint may still execute internally, so Production scans are blocked by default unless the agent is routed through the Runtime Firewall.

What the endpoint must returnA JSON response with assistant text and optional tool_calls. If the response reports that a tool was executed, AgentGuard marks the scan unsafe and tells you to stop production scanning until the executor is isolated.

Agent security testing checklist

  • Every tool has an explicit allowlist entry.
  • Retrieved content cannot override trusted server data.
  • Object-level authorization is checked before tool execution.
  • Malformed and conflicting arguments fail closed.
  • Side effects require a fresh policy decision.
  • Runtime decisions produce auditable evidence.
